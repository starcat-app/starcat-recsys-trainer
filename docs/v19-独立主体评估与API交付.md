# v19 独立主体评估与 API 交付

> 日期：2026-11-03。状态：独立主体确认通过，重训 Bundle 已部署，公网 API 验收通过。
> 用户已授权推进到经过质量与接口验收的生产模型；不是要求绕过门禁强行上线。

## 1. 固定输入与评估限制

复用 v18 修复后的 Dataset：2,061,840 条关系，其中训练关系 2,060,069 条，
13,638 个公开候选仓库。Canonical 固定截至 2026-10-31，不混入未完成的新分区，
不重新下载、不调用 BigQuery。训练预算仍为原有 2% 主体与严格配对上限。

新评估 Artifact 从 Canonical 单独抽样，显式排除全部训练主体，来源参与身份；
不要求命中训练 2%。先按固定盐和 MD5 排序选择有窗口行为的候选主体，再计算
训练期参考目录历史量；主指标仅用 5～200 历史、至少一个可用种子的暖启动主体。
零历史、1～4 历史、超上限主体保留容量统计，不冒充已完成这些群体的推荐质量验证。

首次主体—仓库 Star 用最早事件时间聚合，对重复下载和同 ID 不同事件具有幂等性。
September / October 主体池按哈希另一位隔离；validation 选型，随后只对一个冻结
候选读取 October 确认集，不能用确认集再选其他权重。

明确限制：

- 10 月窗口此前已观察；这是新增主体留出，不是未知的前瞻时间测试。
- metadata 是当前快照，存在存活及事后内容信息偏差。
- 主指标保留已知公开 metadata 中的目录外标签，不能按训练目录悄悄裁剪真值。
  缺 metadata、已归档或不可公开确认的标签另记数量，不能把它称为所有 GitHub
  后续行为上的完全端到端召回。
- 查询最多用最近 20 个训练目录种子，排除完整已知公开历史，与在线种子预算一致。
- 宏平均每个主体权重相同；逐主体散列结果只留私有数据目录，不能进入 Bundle。

首轮 100,000 候选主体容量盘点得到 validation 4,248、确认集 1,154，低于预先目标。
没有读取模型成绩，先扩大候选池预算到 1,000,000，保留原容量结果和协议不覆盖。
每个窗口仍最多 10,000 主体，不能在看成绩后按是否命中重新选人。

扩大后的实际池为 711,732 个候选主体，没有触及 1,000,000 上限；validation 可计算
主体 29,713，按既定顺序取 10,000；确认集全部 8,395 个，均无训练主体交集。
候选池历史分层为：0 历史 351,650，1～4 历史 115,094，5～20 为 99,621，
21～50 为 57,122，51～200 为 64,108，超上限 24,137。
入选主体有 22,697 条留出期首次关系不在当前公开活跃 metadata 范围内；该容量统计
涵盖入选主体的整个留出期，不等于最终确认集的目录外真值条数。

## 2. 候选与放行门槛

基线：修复后同输入 co-star，support2、cap100、365 天半衰期、shrinkage10、top100，
严格配对预算 2 亿。候选为 support0.5、公开 metadata TF-IDF，以及两者的倒数排名
融合（content weight 0.25 / 0.5 / 0.75）。Popular 仅作无关联基线。

TF-IDF 使用名称、描述、topics、语言，不使用留出行为或 stars 作为内容特征。
单线程分批近邻与 Parquet 写出，不把百万推荐边累积进 Python 内存。
内容可补无共现边种子，但不声称解决目录外新仓的冷启动。

在读取模型成绩前冻结：

1. validation 按 Recall@20、再 NDCG@20 选择一个候选。
2. 确认集至少 5,000 个有效主体。
3. 确认集 Recall 不低于同输入 support2，NDCG 至少为基线 98%。
4. 同主体配对 Recall 差异的 90% bootstrap 区间下界大于 0（2,000 次，seed7）。
5. 确认集空结果率不超过 10%；同时报告目录覆盖和目录外真值损失。
6. 固定产物、源码和协议校验和，训练期间不改变本地 Registry active。

这些是本轮受限离线发布门槛，不是声称所有用户、所有新仓与线上留存均已达标。
未来完整日期的前瞻确认、实际“不感兴趣”反馈与分群指标仍需后续补充。

### 实际质量结果

validation 唯一选中 `hybrid_25`，以下为选型冻结后的同主体确认结果：

| 模型 | Recall@20 | NDCG@20 | MRR@20 | 实际推荐目标覆盖率 | 空结果率 |
|---|---:|---:|---:|---:|---:|
| support2 基线 | 0.025261 | 0.010832 | 0.007035 | 0.046595 | 0.011793 |
| hybrid_25 | 0.035086 | 0.013851 | 0.008389 | 0.161359 | 0 |
| Popular | 0.011779 | 0.005903 | 0.004310 | 0.003669 | 0 |

Recall 相对提升约 38.9%，NDCG 约 27.9%。配对差异的 90% bootstrap 区间：
Recall `[0.007263, 0.012561]`，NDCG `[0.001823, 0.004219]`，
MRR `[0.000166, 0.002513]`，均未穿过零；全部预设门槛通过。

确认集主召回包含 9,206 条已知公开真值。辅助目录口径以训练样本有观测的 13,628 个
仓库为分母，其中真值 7,942 条（86.27%）；Bundle 完整目录为 13,638 个，不能把这
两个数字混用。额外 10 个无训练样本观测的候选影响确认集 1 个主体，但三种确认模型
均没有命中该标签，已单独聚合核对，不影响本轮主指标、辅助召回或放行结论。
评估器另补回归，保证目录内辅助召回只统计对应交集，不会因目录外命中超过 1。

目录，运行时数据和真实根路径不提交。成功后按选定参数 refit 最新固定水位，并
明确 Bundle 引用重训前评估，不能将 refit 模型伪称同模型实测。

实际 refit 保留相同 59,940 个训练主体、目录与准入权重，把其 2,061,840 条截至

## 4. 生产 API 核验

生产目标为 `starcat-api` 聚合内的 Recommend，业务请求需 `X-SC-Svc: recommend`。
本轮前只读核对：鉴权查询可达；v2 没有 active，返回 `MODEL_UNAVAILABLE`；发布密钥
尚未配置。因此不能把本地 v16 active 当生产已部署模型。

质量通过后才生成不可变候选 Bundle；先做真实 ZIP → 隔离 Registry → HTTP 的本地
契约验收，再配置独立发布密钥并交付。客户端业务密钥与发布密钥严格隔离。
上线验证实际 model_version、代表性结果、分页、去重、自推荐排除、ETag/304、401。
生产没有旧 active 时，需保存可用回退 Bundle；不重启其他服务来替代模型验收。
