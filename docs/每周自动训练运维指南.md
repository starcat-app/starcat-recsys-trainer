# 每周自动训练运维指南

每周日北京时间 11:00，由 Studio 当前用户的 LaunchAgent 触发。机器的系统时区应为
`Asia/Shanghai`；任务登录后自动加载，补跑最近一次漏掉的周次。每日 10:00 的
WatchEvent/History 下载任务独立运行，每周训练只读取已经完整下载的 Raw，不调用 BigQuery。

## 训练与发布规则

沿用已验收的训练主体、权重、核心目录及扩容目录，每次生成新的不可变 run。配方为
75% co-star 与 25% 内容倒数排名融合，加上独立 TF-IDF 内容补充索引。co-star 维持
365 天半衰期、support 0.5、每主体最多 100 仓库、2 亿配对预算和 Top 100。

数据按增量水位更新，模型对有界 Dataset 完整重训。Raw 不复制进 run：从原始分区
计算固定训练主体和新留出主体的首次 Star，避开旧 Canonical 的事件 ID 去重问题。
主体只留在私有训练数据里，Bundle 只含公开仓库、聚合推荐边和内容索引。

首次留出起点取「目标截止时间减七天」与「线上模型训练截止时间」中较晚者。样本不足
时固定这个起点、延长终点，后续周持续积累。发布成功后才重新开启下一轮时间留出。
训练主体与评估主体完全分离；评估最多 10000 人，每人最多 20 个 seed，排除完整历史。
目录外但在已知公开 metadata 中的真值不会按核心训练目录裁剪。metadata 是冻结快照，
评估只证明当前暖启动、已知公开目录口径，不代表所有新项目的推荐质量。

发布必须同时满足：

1. 从 checkpoint 起点到最新完整 UTC 日无缺分区，schema、footer 行数和 SHA-256 全部匹配
2. 至少 5000 个有效评估主体，新旧模型使用相同数据、seed 和排除规则
3. Recall@20 和 NDCG@20 均不低于线上模型；空结果率不高于线上且不超过 10%
4. 旧版有出边的源不变空，已有内容索引目标不丢失，无自身推荐和非法边
5. Bundle 必要文件、checksum、SQLite、版本与评估来源校验全部通过
6. 真实 Go API 的隔离 Registry 验收通过，包括分页、去重、排除、ETag/304 和鉴权

确认通过后，固定原训练主体和权重，将它们的有效行为推进到最新水位 refit；最终 Bundle
明确标记 `metrics_scope=pre_refit`，不把重训前分数冒充最终模型实测。最终 Bundle 再经过
覆盖检查与隔离 API 验收，才允许上传。固定主体、目录、源码和本次 Raw 若在运行期间变化，
会阻止交付。

发布前读取真实生产 active 并保存固定公开源的基线；上传后回读版本、验证真实查询、内容
补充、分页、缓存和多种子排除。失败时重新查询 active，必要时上传原不可变 Bundle 回退，
并验证回退结果。上传超时不等于服务端未激活。回退失败或结果无法确认会保存失败证据，
不会记作成功。

## 配置与安装

以 `configs/example-weekly.yaml` 为模板，填写已存在的产物位置，保存到
`~/.config/starcat/weekly-recommendation.yaml` 并设置权限为 `600`。运行参数不包含
凭据值，查询 Key 与发布 Key 分别保存在权限为 `600` 的私有文件中。

首次使用自己的公开数据时，按[训练指南](TRAINING-ZH.md#初始化每周训练)生成初始配置，
无需官方冻结主体。需要 Python 虚拟环境、Go 和 `starcat-recommend-api` 源码。
隔离验收使用 `GOWORK=off` 及 API 已锁定的模块依赖，无需同级 `starcat-api-kit`。

```bash
./scripts/install-weekly-recommendation-launch-agent.sh render
./scripts/install-weekly-recommendation-launch-agent.sh install
./scripts/install-weekly-recommendation-launch-agent.sh status
```

安装会立即进行一次到期检查；若有漏跑周次，将开始真实流程。用户配置覆盖变量为
`STARCAT_WEEKLY_RECOMMENDATION_CONFIG`。

生效配置是 `~/Library/LaunchAgents/com.starcat.weekly-recommendation.plist`，日志是
`~/Library/Logs/Starcat/weekly-recommendation.log`。状态文件位置由 `state_file` 指定。

## 查询、补跑与故障恢复

```bash
./scripts/run-weekly-recommendation.sh status
./scripts/run-weekly-recommendation.sh run
```

`run` 是有副作用的真实训练入口，满足全部门槛后会自动发布，没有强制放行开关。
`status` 只读。运行锁使用用户目录中的内核文件锁，关机后自动释放；`caffeinate`
跟随真实 worker 防止训练期间自动休眠。

阶段完成后保存 artifact checksum；同一水位中断后使用相同输入与源码恢复，只重建
尚未完成阶段自己的产物。已完成文件损坏会停止，不隐式接受或覆盖。生产发布阶段保留
发布前回执，支持服务端已激活但客户端尚未写成功状态时续验。

| 状态 | 含义 |
| --- | --- |
| `running` | 锁仍被训练进程持有，`stage` 表示当前阶段 |
| `interrupted` | 状态仍写运行中，但实际运行锁已释放；可以补跑 |
| `blocked` | 数据没有更新，或质量/覆盖不足；生产模型未更新 |
| `failed` | 数据、训练或接口验收失败；检查对应阶段日志与回退记录 |
| `published` | 新版本已激活，生产查询验收通过 |
| `not_due` | 本周已处理，登录加载时无需再跑 |

私有 run 内保存 `run.json`、配置与源码快照、人口统计、同输入新旧模型评估、隔离 API
日志，以及发布/回退回执。报告只打印聚合指标和版本，不能复制主体明细或凭据到 Issue。

## 公开成果与模型分发

每次终态运行自动在 `<workspace>/public/docs/` 更新成果，成功、受阻与失败分别记录。
`public_distribution.enabled` 默认关闭；显式启用并给调度进程注入独立 GitHub 凭据后，
成功上线模型会发布完整 Release，并同步公开历史。分发失败只标记
`distribution.status=pending`，不重训、不回退已上线模型。配置、预览与独立补传步骤见
[模型分发指南](MODEL_RELEASES-ZH.md)。

## 开发验证

```bash
make check
bash -n scripts/run-weekly-recommendation.sh scripts/install-weekly-recommendation-launch-agent.sh
git diff --check
```

集成测试使用 4999 与 5000 个合成留出主体，实际训练并导入隔离 Go API；生产 HTTP 由
替身接收。另测上传已经激活但响应丢失后的回退。真实生产首轮必须另看运行结果，测试
通过不能替代真实数据达到质量门槛。
