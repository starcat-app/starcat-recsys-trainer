# 候选训练与本地验收

本流程用于 v17 及后续受控训练：先同组评估，再以最新有效行为重训，产出待验收 Bundle。
这里的候选生成不是上线发布，也不表示功能总览可以勾选完成。

## 1. 不改变活动模型

在正常 `pipeline run --config ...` 的 YAML 中显式设置：

```yaml
publish:
  model_version: example-candidate-v1
  selected_model: costar
  install: false
  metric_gates: {}
```

Bundle 只写在本次 run 的 `published/<model_version>/`，不调用 Registry 的 `install`，
不写其版本目录或 `active.json`。此时配置 `publish.recommend_api` 会在采集之前报错。
省略 `install` 保持既有管道的安装行为，因此每次候选运行都必须明确检查该值为 `false`。
同一 run 或同名候选不能覆盖；失败重跑使用新的 run_id。

## 2. 固定主体与权重

`dataset.frozen_cohort_catalog` 指向既有公开参考仓库目录 Parquet，只读取其中的 repo_id。
指定后，主体准入的最小 / 最大仓库数和权重分母全部使用“参考目录内、训练期之前”的计数。
新增目录仓库、验证与测试行为不改变本轮对照的准入和权重。缺少目录会失败，不会隐式
退回动态主体规则。没有设置时，原管道的行为保持不变。

参考目录不等于向模型提供用户身份。主体值只留在训练 Dataset，ServingBundle 仍只含
公开仓库与聚合推荐边。元数据是当前快照，不能把这种回溯评估宣称为完全重建当时可见目录。

```yaml
dataset:
  train_end: "2026-09-01T00:00:00Z"
  validation_end: "2026-10-01T00:00:00Z"
  frozen_cohort_catalog: ./inputs/reference-repositories.parquet
  minimum_repositories_per_subject: 5
  maximum_repositories_per_subject: 200
  subject_sample_rate: 0.02
training:
  reference_time: "2026-09-01T00:00:00Z"
  minimum_support: 0.5
  maximum_repositories_per_subject: 100
  maximum_pair_observations: 200000000
  require_full_pair_budget: true
  train_svd: false
  run_ablations: false
```

同组比较必须复用同一输出 Dataset；旧目录对照只裁剪训练记录，不重建评估人群。
`require_full_pair_budget=true` 会在训练前计算实际 capped 配对数，超过预算直接失败，
不允许原配对预算策略悄悄训练部分主体。`support` 是时间和主体加权支持度，不是整数人数。
`train_svd=false` 仅跳过 SVD，不表示它已被本轮评估淘汰。

## 3. 评估与最终重训分离

参数只在 validation 阶段选择，随后固定候选再读 test。保存完整比较表、输入校验和、
各阶段时间边界和切片指标，不用模型目录数冒充推荐覆盖，不反复查看 test 调参。

最终重训可将 train_end 移到已确认的数据水位之后，使全部有效训练行为进入 train；
validation_end 仍须晚于 train_end。重训不伪造空验证集的成绩，而是显式引用此前 test 报告：

```yaml
evaluation:
  reference_metrics: ./evaluated-run/evaluation/test-metrics.json
publish:
  model_version: example-refit-v1
  selected_model: costar
  install: false
  metric_gates: {}
```

引用文件必须是 test，包含有效评估主体和选定模型 checksum，且只能在不安装模式使用。
Bundle 的 `metrics_scope=pre_refit` 表示这是重训前评估；`evaluation_checksum` 与
`evaluated_model_checksum` 关联真实评估产物。最终模型自己的 checksum 记录在输入列表，
不能把两者混为一个模型。正常直接评估的 Bundle 标记 `same_model`，若报告 checksum
与待构建模型不一致则失败。运行 manifest 还记录实际源码与依赖锁文件摘要。

评估文件应由操作者核对与选定参数、数据水位和训练配置的关系；单凭路径存在或引用成功
不构成晋级证明。没有预先通过质量对照，不应开始最终重训或生产发布。

## 4. 本地 API 验收

在独立 `starcat-recommend-api` 仓运行：

```sh
STARCAT_TEST_CANDIDATE_BUNDLE=/local/path/to/published/candidate \
  go test ./server -run '^TestCandidateBundleLocalAcceptance$' -count=1 -v
```

测试只启动 `httptest` 的本地临时服务，在 `t.TempDir` 的隔离 Registry 加载候选；
不读取 `.env`，不使用任何生产 Key，不向现有本地或线上 Registry 写入，不请求 SimRepo。
原 Bundle 全程只读。覆盖真实 Python 产物导入、版本、鉴权、分页去重、ETag/304、
多种子排除和无覆盖空结果，并报告耗时。主流 / 长尾的内容相关性抽查需另外记录，
这些契约断言不能替代推荐相关性验收。

生产发布、原 Registry 激活、客户端切换、提交和推送均需另行授权。
