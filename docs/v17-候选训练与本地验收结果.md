# v17 候选训练与本地验收结果

> 记录日期：2026-11-02。结论：近期测试门槛未通过，停止最终全量重训，不晋级。

## 1. 范围与数据

复用截至 2026-10-31 的既有 WatchEvent Canonical，没有重新采集 Raw、引入 PushEvent、
安装模型或向远端交付。Registry active 前后摘要一致，仍为既有 v16。

本轮完成正式管道的参考目录准入与权重冻结、严格配对预算、独立候选输出及评估溯源。
参考目录冻结的是计数规则；随训练截止时间推进，主体数量仍可变化，不能宣称跨时间
切分始终是同一批主体。本轮四个近期对照复用同一份 Dataset，旧目录仅裁剪训练记录。

| 项目 | 结果 |
|---|---:|
| Canonical 输入记录 | 511,284,530 |
| 公开候选目录 | 13,638 |
| 有效训练主体 | 59,934 |
| Dataset 总记录 | 2,061,640 |
| train：早于 2026-09-01 UTC | 2,059,869 |
| validation：2026-09-01 至 2026-10-01 UTC | 1,480，1,121 个主体 |
| test：2026-10-01 至 2026-11-01 UTC | 291，274 个主体 |
| 有效行为最大时间 | 2026-10-31 21:54:06 UTC |

数据水位到达 10 月底不代表近期样本充分。固定目录、主体准入与首次 Star 去重后的
10 月评估仅 274 人，结果存在较大不确定性；尚未定位 Raw → Canonical → Dataset
各层导致近期样本减少的贡献，不能直接归因为下载缺失或市场行为变化。
10 月也是此前较长测试窗口的一部分，本轮不是完全从未观察过的新测试集。

## 2. 补齐旧目录同阈值对照

先在此前的固定时间切分上补做旧目录 support0.5，只读取 validation，没有再次读 test。
cap100、固定权重及其余参数保持一致。

| 评估人群 | 旧目录 support0.5 Recall@20 | 扩容目录 support0.5 Recall@20 |
|---|---:|---:|
| v15 人群：9,532 人 | 0.057815 | 0.057258 |
| v16 人群：9,781 人 | 0.044051 | 0.045765 |

扩容在人群不同的两组比较中并非全面获胜，不能把降低支持度的收益全部归因于目录扩容。

## 3. 近期 validation 选型

参数统一为 cap100、top100、365 天半衰期、legacy weight 0.35、shrinkage 10，
严格配对预算 2 亿。只比较目录和加权支持度，不训练 SVD，不由此判定 SVD 已被淘汰。
support0.5 是加权支持度，不是半个用户。

| 目录 / 支持度 | Recall@20 | NDCG@20 | MRR@20 | 推荐目标覆盖率 |
|---|---:|---:|---:|---:|
| 扩容 / 0.5 | 0.034664 | 0.014875 | 0.009913 | 0.065674 |
| 旧目录 / 0.5 | **0.035177** | **0.015118** | **0.010078** | 0.054593 |
| 扩容 / 2 | 0.028568 | 0.013237 | 0.009128 | 0.038010 |
| 旧目录 / 2 | 0.031096 | 0.014156 | 0.009762 | 0.036542 |

四组均为同一批 1,121 个评估主体。先以 Recall、再以 NDCG 在两组 support0.5
中选出旧目录候选；同规则在 support2 中选出旧目录基线。
候选、基线、数据与模型摘要及门槛先写入 `selection-before-test.json`，之后才读取 test。

预设条件：候选 Recall 不低于基线，NDCG 不低于基线的 98%。

同为 274 个主体。候选 Recall 下降约 33.3%，NDCG 下降约 24.3%，未通过。
脚本非零退出，`decision.json` 记录 `passed=false` 与 `registry_active_unchanged=true`。
没有读取其他候选的 test 来重新选型，没有进行最终 refit，也没有生成通过质量门槛的
最终 v17。此前正式管道生成的近期扩容 Bundle 仅保留为实验与契约验收产物。

## 5. 本地 API 契约验收

对近期扩容 Bundle 执行只读校验：checksums、SQLite `quick_check` 通过；
含 13,638 个仓库、116,843 条边、4,523 个有出边仓库、3,870 个推荐目标。
有出边目录占比约 33.2%，不同于上表评估过程中实际推荐目标的覆盖率。

`TestCandidateBundleLocalAcceptance` 实际执行，通过 Python Bundle → ZIP 导入 →
隔离 Registry → HTTP 查询链路。测试只用 `httptest`、临时目录和测试凭据，
不读 `.env`，不调用 SimRepo，不触碰既有 Registry。

- 40 个有覆盖种子，包括低 Star 样例。
- 单仓分页、自推荐与跨页重复、模型版本、ETag/304、多种子排除、未知种子空结果和 401。
- 本机单页 P50 0.371 ms、P95 0.671 ms；查询阶段约 37.4 ms。

这是本机临时 HTTP 服务数据，未包含公网延迟，也未证明质量未通过的旧目录候选可晋级。

扩容 Bundle 的公开项目抽查：

| 种子 | 前列目标样例 | 观察 |
|---|---|---|
| microsoft/vscode | microsoft/TypeScript、torvalds/linux、nodejs/node | 开发工具相关，但也有跨领域热门仓库 |
| golang/go | gin-gonic/gin、kubernetes/kubernetes、avelino/awesome-go | Go 生态较明确 |

| swiftlang/swift | realm/SwiftLint、JetBrains/kotlin、Alamofire/Alamofire | Swift 生态中仍混有跨语言目标 |

少量样例不能代替盲评。空结果可能来自目录缺失、改名或无出边，不能只凭名字查询空
就断言模型遗漏某个 repo ID；长尾无覆盖与热门偏置仍需专项评估。

## 6. 复现与代码门禁

本机训练根下保留三个独立目录：

- `gharchive-v17-old-catalog-control-20261102`：旧切分的同阈值对照。
- `gharchive-20261031-v17-recent`：正式近期 Dataset、模型、评估及实验 Bundle。
- `gharchive-v17-recent-controls-20261102`：近期四组对照、选型冻结与失败决议。

配置与执行脚本归档在近期对照目录的 `reproduction/`。JSON 产物含数据与模型摘要，
共享 active 在正式运行包装脚本和对照脚本中分别作前后检查。
近期长任务开始后曾补充源码摘要和质量报告目录摘要字段，因此该 run 不含后来新增的
这两项溯源；不得补写成运行开始时已捕获。后续管道已支持启动时记录源码与锁文件摘要。

Trainer `make check`：148 项测试、Ruff、mypy 全部通过，覆盖率 88%。
Recommend API 完整 `make check` 已通过，另以上述真实产物定向测试补充验收。

后续优先检查近期样本的逐层保留率、稳定事件身份去重和目录/主体筛选损失，再确定新的
实验协议。不要在本轮已看过的 test 上继续筛参数；在新的协议确认前，保留现有活动模型。
