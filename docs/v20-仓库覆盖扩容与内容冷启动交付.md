# v20 仓库覆盖扩容与内容冷启动交付

> 日期：2026-11-03。状态：内容索引训练、聚合服务部署及公网验收完成。
> 本轮优先扩大单仓推荐覆盖，保留 v19 共现排序；不把覆盖扩容称为新的行为召回提升。

## 1. 范围与数据

生产 v19 的候选目录为 13,638 个公开仓库，只有目录内预计算边可用于单仓推荐。
源项目不在目录中，或没有预计算出边时，客户端会得到空列表。本轮增加一个公开
metadata 内容索引，让这些源项目也能检索目录内候选，不上传用户完整 Stars。

复用既有公开 metadata 缓存，并按二十种语言查询公开、非 Fork、未归档且
至少 100 Star 的近期更新项目。每种语言最多三页、每页一百项，总请求预算六十次，
请求间隔 6.2 秒；保留原始公开响应快照以便重放。已存在的 v19 核心 metadata 优先，
不通过修改其描述或 topics 顺便改变旧推荐。

这不是全 GitHub 候选目录。Search 与现有缓存具有语言、活跃度和 Star 门槛偏差。

BigQuery 查询、Raw 全量重下载或训练主体重抽样。

## 2. 训练与在线路径

新增 `ContentIndexTrainer`，使用名称、描述、三倍 topics 和两倍语言拟合
TF-IDF。采用小写 unigram、英文停用词、sublinear TF、L2 归一化，特征上限
50,000；词表和稀疏倒排向量附加到 Bundle 的 SQLite：

```text
content_vocabulary(term, idf)
content_postings(term, repo_id, weight)
```

仍按原三文件 Bundle 契约发布，manifest 标明 `content_fallback` 来源和训练摘要。
v19 的共现模型、预计算排序及分数不重新选型；原评估指标仍为 v19 重训前指标，
不能当作 v20 内容检索的新行为质量证明。

单仓查询顺序：

1. 有预计算出边时，继续返回原推荐；翻到越界页不能跳入内容检索。
2. 没有出边时，优先读取 Bundle 中的源仓库 metadata。
3. 源不在 Bundle 中时，由配置了 PAT 的服务端按数值 GitHub 仓库 ID 查询公开
   metadata；私有、归档、禁用、缺失或返回 ID 不符的源不进入向量检索。
4. 查询向量与候选倒排向量点积，最低余弦相似度 0.08，排除自身，按分数和
   repo ID 稳定排序，以 `limit+1` 分页。

内容结果带 `fallback=true`、`metadata_tfidf` 信号，不伪造共现结果的
`display_score`。源 metadata 摘要追加到有效 `model_version`，分页与 ETag 使用
实际版本；确定快照后才能判断 304，避免源描述变化后继续命中旧内容。

本次只补单仓接口；多 seed 推荐继续使用原预计算边，没有声称已经实现个性化
目录外冷启动。中文描述、没有 topics、只有泛化仓库名等来源可能得到弱关联结果；
这是词法相似检索，不是多语言语义模型，也不保证所有公开项目都有充分依据。

## 3. 网络、缓存与隐私边界

- 目录外元数据仅由服务端 PAT 查询；客户端不持有 PAT，查询不等于授权训练贡献。
- 公开元数据缓存七天，不可用来源十五分钟；容量 4,096 条，按过期时间淘汰。
- 同源请求合并，上游并发为二，请求间隔 720ms，可取消，含等待的预算八秒。
- 上游失败触发一分钟退避；瞬时错误返回可重试错误，不保存成永久空推荐。
- 未配置 `GITHUB_TOKENS` 时不隐式联网；Bundle 目录内内容检索仍可使用。
- 聚合使用 `RECOMMEND_GITHUB_TOKENS`，复用现有服务端公开 metadata 凭据。
- 元数据读取复用 API-Kit 的数值 ID 方法；HTTP 不跟随重定向，不向客户端传递
  上游错误正文。没有发送用户标签、笔记、私有仓库或训练主体。
